# AWS EC2 / Nginx 初回ハンズオン

EC2 上の Nginx に対する HTTP 接続と、Security Group の受信ルールによる到達性の変化を確認した学習記録です。

## 記録の範囲

過去の実習会話で本人が報告した結果のみを実績として記載しています。今回 AWS 環境に接続して再検証したものではありません。スクリーンショットや生ログは公開していません。

| 項目 | 会話で確認できた結果 |
| --- | --- |
| EC2 ステータスチェック | システム・インスタンス・EBS の 3/3 合格 |
| EC2 Linux への接続 | success（接続方式は未確認） |
| Nginx | active |
| 通常時の内部 curl | HTTP 200 |
| 通常時の Mac ブラウザ | success |
| HTTP 80 受信ルールを遮断した際の外部ブラウザ | timeout |
| 同じ遮断試験での内部 curl | HTTP 200 |
| HTTP 80 ルール復旧後 | success（復旧後の HTTP ステータス値は未報告） |

OS・AMI・リージョン・インスタンスタイプ・接続方式・実行コマンド全文・内部 curl の宛先・実際のルール送信元 CIDR は未確認です。費用額、無料枠の適用、リソース削除完了も未確認です。

## 構成の概念図

```text
Mac ブラウザ → HTTP/TCP 80 → Security Group → EC2 / Nginx
                                               ↑
                                          内部 curl
```

概念図は接続関係の説明用です。VPC・ルート・サブネット構成を検証済みとして表すものではありません。

## 学んだこと

外部接続が timeout でも、内部から HTTP 200 が返る場合があります。今回の結果は、Nginx の稼働と外部からの到達性を分けて調べる必要性を示しています。HTTP 80 のルール変更・復旧と外部接続結果の対応は、Security Group の影響と整合します。内部 curl だけで外部経路の正常性を証明することはできません。
